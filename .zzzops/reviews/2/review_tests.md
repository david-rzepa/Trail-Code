# G2 test design review

Decision: changes requested.

The real Node and Go fixtures are useful: they exercise actual analyzer results and full runner baselines and require selective execution of affected targets, including a Go dependent outside a bounded package. The 7.8-second red measurement only reaches the missing verification seam; it does not establish the cost or behavior of the completed tests. There is no basis yet to call that cost disproportionate. The following omissions leave required behavior unverified:

1. The mutations in the conditional-requirements test only alter the analyzer report. There is no test where the independently observed runtime, runner, inventory, resolver, inputs, environment, baseline, Go build tags/platform/dependencies or discovery is actually missing, incompatible or stale while the report remains plausible. Nor is evidence substituted from another commit, profile or inventory. Add representative real collector/context changes, including incomplete discovery and triggered dependency context, and assert full fallback without trusting the analyzer; include explicit Go context cases.
2. Receipt tests cover a missing baseline and issuance of a receipt, but do not verify compatibility or predecessor-chain reuse, invalidation for profile/context/inventory/model changes, failed/partial/cancelled runs, corrupt or missing predecessor, or the specified receipt-store trust boundary and safe publication. Add focused tests for these cases, including forged tracked receipts, unsafe symlink/replacement paths, partial writes and concurrent publication. Assert no invalid evidence yields selective execution or a passing receipt.
3. All verification calls use a private injected fixture profile/seam. No test exercises the production entry point and this repository's actual npm test workflow, its preparation, ordering, logs, gates and full fallback without recursion, JSON stdout isolation, or failure/cancellation propagation. Add a production-path integration test and targeted runner tests that protect those semantics, and check honest stable-input reporting with ordinary preflight rather than proving mid-run immutability.
4. The suite lacks the explicit inverse, deletion and import-rebinding cases, new/modified/deleted test discovery, mixed-language or cross-build boundaries, unvalidated bounded scope and relevant non-code/input invalidations. These are central to safe mapping from the two revisions to runnable targets and can't be inferred from the single forward edit. Add focused tests that establish dependent inclusion or full fallback, including both revisions where applicable.
