# Conditional Go package impact model

Schema v2 can report `go-static-packages` version `1` as conditional for a single committed Go module. It reads raw source from each pinned tree and constructs fresh package, import and exact embedded-file relationships. All package source and test files depend on their package peers. Each static local module import relates the importing file to all files of the imported package, including initialization and tests; closure is computed independently for both revisions without depth limits. Import reasons retain the literal module specifier and target path. Exact `//go:embed` file dependencies include the embedded path, including documentation if explicitly embedded. These conservative package edges may select more tests than necessary. When embedded bytes change, their content is opaque: the report emits a bounded `opaque_embedded_resource` gap for `go-package:<module>:<package-path>`, records the model, revision tree and package boundary, and requires that scope and all its importing dependent targets. The consumer must independently validate this boundary and mapping; if it cannot, it must run the full profile.

The initial adapter accepts a root `go.mod` containing only a module declaration and Go version, local imports that resolve to tracked package directories, and the fixed standard packages `testing` and `embed`. It accepts exact single-file embed names, and treats unembedded README.md and LICENSE files as documentation because supported code cannot access the filesystem through unmodeled Go imports. Each package must have consistent package declarations. Unknown files or imports, external modules, cgo, platform-specific filenames, build constraints, generation or other Go directives, embed patterns, invalid encoding and parser recovery require full fallback. A change to `go.mod` also requires full fallback. Additional Go language/build features are not inferred from parser success; no cross-language support is claimed.

Singleton requirements use the v2 common registry IDs and evidence collectors. For this model `runtime` uses `supported_go_runtime` and `resolver` uses `supported_go_package_resolver`; each predicate includes the `go_version` declared in go.mod. `runner` and `inventory` must independently establish package-level `go test` execution, complete target discovery, package-to-target mapping, and that package execution and initialization match the modeled graph. The runtime and resolver evidence must cover the actual Go toolchain, version, GOOS, GOARCH, build tags and flags, module resolution and standard library. Each imported standard package adds `dependency:<name>` with predicate `go_standard_package_matches_runtime`, a `specifier` parameter and `dependency_observation` evidence. All other singleton requirements cover inputs, environment and a compatible baseline as specified in the v2 contract. The consumer must independently derive and validate every singleton and triggered requirement, including any external input, resource, tool or configuration, against the actual planned execution. Unknown models, unsupported settings or unverified evidence force full-profile fallback.

This report is a conditional dependency analysis, not a passing result or proof that later execution inputs remain unchanged. The execution layer performs its ordinary target preflight and reports its stable-input assumption.
