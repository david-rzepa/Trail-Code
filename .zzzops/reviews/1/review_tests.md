# Test review

Changes requested. The suite runs the real CLI against temporary Git repositories, and its measured 9.6-second red run reaches all 11 cases; the failures are expected before implementation and do not establish green behavior. The integration cost is reasonable for the distinct endpoint and graph scenarios, with no explicit sleeps or fragile timing assertions. Three safety-critical contracts remain insufficiently tested:

1. `worktree target includes staged...` only exercises a static worktree and permits any nonzero result with a matching diagnostic. It does not exercise a mutation or loss of observation during capture. A capture that combines bytes from two filesystem states, misses an addition or edit-and-revert, or treats an overflow as success would pass. Add deterministic capture-level tests for mutations spanning enumeration/reads/sealing, addition/rename, edit-and-revert and observer loss/overflow; assert retry or failure without a valid snapshot. Test the supported capture path directly rather than allowing unconditional failure to satisfy all worktree checks.
2. `cold and warm analyses` compares identical snapshots twice, but never changes snapshot, analyzer identity, mode, or cache contents. An implementation that always reuses an old graph or accepts a navigation-mode/incompatible cache can pass. Add tests that prime a cache then change relevant source/snapshot identity, mode/version or cause refresh failure; require an updated report or an explicit incomplete/fallback result, never stale success.
3. `unmodeled dynamic behavior` accepts a dependency reason on the changed file as a substitute for a gap, without identifying the dynamic call's possible targets or dependent tests. An analyzer that reports only the changed registry and silently omits its unbounded dynamic dependencies passes. Assert a justified bounded dependency relationship that covers the candidate targets or an explicit gap with appropriate fallback; for this unbounded global lookup full-profile fallback is a safe baseline. Also enforce bounded/incomplete status consistency against gaps and fallback scopes, rather than only checking complete/no gaps and incomplete/full fallback.
