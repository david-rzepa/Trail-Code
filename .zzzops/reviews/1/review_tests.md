Changes requested. The revised tests correctly reject `worktree`, compare identical committed trees across dirty checkout states, exercise unsafe Git symlink entries without requiring host symlink privileges, and inject moved-ref, Git-object and materialization faults. The cached-graph safety cases remain covered. The observed 18.3-second CLI run passed all 22 cases; the 0.14-second coordinator run has six passes and five expected failures because the new snapshot seam has not yet been implemented. The added subprocess journeys are justified by distinct Git link cases.

One material security assertion is missing: `assertUnsafeLinkFailsClosed` only checks that the external sentinel's literal bytes are absent from stdout/stderr and unchanged afterwards. An analyzer can follow an absolute/escaping symlink, read and parse the external secret, suppress its literal contents in the report, and still emit an unbounded gap and full-profile fallback; all the current assertions then pass despite the design's prohibition on importing external bytes under a pinned tree identity. Include a deterministic test of the production materialization/object-reading boundary that detects or prevents the attempted external read itself (for example an injected no-follow read trap), plus a real Git-linked external sentinel scenario where its changing contents cannot influence analysis. Cover the chained/path-component variants and ensure cleanup never follows the escape. A fallback alone does not satisfy the no-external-read guarantee.
