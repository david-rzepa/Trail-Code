# G1 implementation re-review

Changes requested. The original replacement-ref bug is fixed, and the packed Linux artifact now records a grammar hash and reuses its cache. An unchanged repository consisting only of a simple export also returns a valid empty result. The unconditional fallback for changes remains material, and the new package identity and cache code still has two platform/runtime defects.

## Full fallback remains unconditional for every changed tree

The previous finding remains open. `src/impact/analyze.ts:227-234` adds `unmodeled_dependencies` and full-profile fallback for both revisions for **every** nonempty changes array, regardless of the actual files or graph facts. This means there is no changed comparison on which a consumer can select a subset, even when the repository contains only an analyzable local function. It defeats the goal of determining which tests to run based on a changeset, and has no tested supported subset or bounded scope; safe fallback for *genuinely* unresolved relationships must remain, but all relationships being treated as incomplete is not the requested impact analysis.

The no-change correction is also narrower than its response suggests: on the reviewed build I created a repository containing `export function add(a:number,b:number){return a+b;} export function run(){return add(1,2);}` and compared its commit to itself. It returned zero changes but `incomplete`, `unresolved_call`, and `full_profile`. `preserveCandidates` marks even the directly resolved local call as not exhaustively resolved. The test only exercises `export const value = 42` and doesn't cover the ordinary function-call case. Establish a sound supported model and scope, including ordinary same-tree/zero-change handling, rather than claiming unknown dependencies are safe; provide a concrete changed example where conservative analysis selects less than a full profile.

## Grammar hash tracks the wrong JS runtime entry point

The earlier lockfile finding is partially fixed on Linux, but its identity requirement is not yet met. `grammarIdentity()` hashes `createRequire(...).resolve('web-tree-sitter')`, which resolves to `web-tree-sitter.cjs`. The actual production breadth/container loader in `src/graph/wasm-runtime.ts` uses dynamic `import('web-tree-sitter')`, which resolves to `web-tree-sitter.js`. At this checkout `require.resolve` and `import.meta.resolve` return those distinct paths, respectively. If the installed ESM runtime changes while the CJS file and wasm remain identical, `grammar_identity` and the raw-cache key do not change, so facts from a different effective parser runtime can be replayed. Hash the actual runtime entrypoint loaded for each parser mode, or otherwise identify all bytes that influence its extraction results.

## Windows cache is always rejected by POSIX permission checks

The new packed-cache test was run on Linux only. `src/impact/analyze.ts:63-74` rejects the `.cache` parent whenever its mode has `0o022`, and later rejects cache directories whenever mode has `0o077`. Node's Windows stat mode is not a representation of NTFS ACLs: libuv synthesizes readable/writable permission bits for owner, group, and others from the Windows read-only attribute ([libuv Windows stat implementation](https://raw.githubusercontent.com/libuv/libuv/v1.x/src/win/fs.c), around `fs__stat_assign_statbuf`). An ordinary writable directory therefore has group/other bits set and the parent check returns null. The created cache directories' mode arguments also cannot establish the assumed POSIX privacy on Windows. As a result no Windows run can reuse this cache and the installed-package test's assertion that cache files exist will fail there. Implement an appropriate portable private-cache/trust strategy (or reliably disable unsafe reuse with a separately supported cache strategy) and exercise it on Windows; do not assume POSIX mode bits prove Windows ACL privacy.

## Resolved findings and test cost

The `--no-replace-objects` global Git argument now applies to all analyzer Git reads, and commit/tree/blob replacement-ref regression tests were added. The earlier test-design request added those tests, a populated unchanged fixture and an actual npm tarball test. The recorded checks passed: 30.8 s contract tests, 0.1 s coordinator tests, 10.1 s packaged test, 6.7 s build, and 708.7 s full suite, with no prior timing baseline. The packed test proves warm cache reads on Linux only; it does not cover Windows ACL behavior or mutations to the ESM runtime actually imported by breadth parsing.
