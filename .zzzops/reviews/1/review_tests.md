# Regression test re-review

Changes requested. The package test invokes npm's JavaScript entry point through Node, with Windows path discovery checked by simulated paths. It no longer runs an unpinned registry install and instead unpacks the real tarball and links existing dependencies offline. These changes resolve the two prior findings; an actual Windows run remains valuable because path simulation does not execute Windows process or junction behavior.

The isolated source build now uses `git archive HEAD`. When a developer changes the implementation or package metadata without committing, the regular `npm test` command runs the installed-package regression against the old committed source, not the current working tree. A fix can still fail locally until committed, and a new regression can pass until committed. Build a temporary copy from the actual test checkout, including relevant tracked modifications and additions while excluding writable output and node_modules, or otherwise ensure the packed test targets the current source. Preserve isolation from concurrent tests and the offline package checks.

Measured at the checkpoint, the 7.9-second packed case exercised npm discovery and offline packaging, but stopped at the expected grammar-identity failure before the warm-cache read assertion. The other targeted runs took 24.3 seconds for real CLI cases and 0.10 seconds for coordinator safety. Those timings are observations, not proof that the packed cache regression passed.
