# Test re-review

Changes requested. The new deterministic capture-backend tests cover mutations across enumeration, reads, and sealing; observer loss/overflow; incomplete coverage; stable capture; and an immutable snapshot. The cache seam exercises wrong snapshot, navigation mode, policy/version, failed refresh and failed publication, and the subprocess cases check real cache and navigation wiring. Those changes resolve the first two findings. The dynamic global lookup test now requires an unbounded gap, incomplete status and full fallback, resolving that part of the third finding.

The third finding remains open because the common report validator still does not check the required consistency in the bounded case. For example, a report with `analysis_status: "bounded"`, a bounded gap, and an empty `required_fallback_scopes` passes `report()`; downstream consumers could then exclude affected tests without including any dependent scope. Add assertions that each bounded gap is backed by an appropriate dependent scope or full-profile fallback, and that status agrees with all gaps, with a targeted bounded-gap scenario where that safety condition can be falsified. A test should fail on missing or contradictory fallback rather than only on the specific unbounded fixture.

The reported separate measurements are 13.6 seconds for 14 real CLI cases and 0.24 seconds for the internal safety suite. The latter currently only reaches a missing-module error, so its behavioral assertions have not yet been exercised; this is explicitly identified in the evidence. The coverage and integration cost are proportionate, with no sleep-based timing in the new tests.
