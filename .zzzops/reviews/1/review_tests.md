# Regression test review

Changes requested. The replacement-ref cases check commit, tree and blob replacement against pinned identity; the populated same-tree case rules out fabricated fallback; the packed-package case reaches a genuine installed distribution and checks grammar identity and warm-cache reads. The changed tests measured 3.3 seconds for the four Git cases and 8.5 seconds for the packaged case on this run; the package run stops before its cache assertion because grammar identity currently fails, so cache reuse has not yet been demonstrated.

Two material execution concerns affect the required `npm test` workflow:

1. The packed test invokes `npm.cmd` with `spawnSync` and no shell on Windows. Windows batch scripts are not directly executable by `spawn`/`execFile`, so the Windows CI leg cannot start the first npm command. Invoke the npm JavaScript CLI via the current Node executable or another cross-platform shell-free method and exercise it on Windows.
2. The test is automatically included in every `npm test`, runs `npm install` in an empty consumer without a lockfile, and fetches runtime dependencies from the registry. A developer or CI environment with an installed project but no network, or a registry outage or different dependency resolution, can now fail the full suite independently of the code. Preserve the genuine packed-install check but make it deterministic and offline-capable (e.g. provide a self-contained dependency fixture/cache and constrain resolution), or move the network-dependent integration into an explicit separately configured gate that retains this coverage. Do not weaken packed artifact and warm-cache assertions.
