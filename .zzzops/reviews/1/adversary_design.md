# Adversary re-review

## Conditional requirement omission

The v2 design requires each reported requirement to be checked and says missing requirements must fall back, but does not define a canonical mandatory requirement set for each supported-model identity, or bind each requirement's kind, expected value, and evidence kind to an independently maintained model contract. A report can therefore omit a requirement—for example, a runtime loader or test-discovery hook—and still contain a nonempty, unique, correctly typed list. A consumer validating only the requirements that appear cannot know that it must measure that omitted input. Schema shape and an allowlisted model/version alone cannot establish list completeness. A report could also relabel a required category as a different evidence kind unless the model contract constrains it.

Require G2 to consult an independently versioned, allowlisted model contract defining the complete mandatory requirement kinds/IDs, expected-value source and admissible evidence bindings, including conditional requirements triggered by the snapshot/configuration, rather than accepting the report's list as the authority. Unknown, missing, duplicated, extra unsupported, inconsistent, or weakened requirements fail closed. Include tests that remove one requirement from an otherwise valid conditional v2 report, substitute an evidence kind, and omit a conditional requirement triggered by discovered input; all must force a full profile or block. Preserve normal matching requirements and an explicit unknown-model fallback.
