# Re-review: independent model requirements

## Truth / supported interface

The registry protects against omissions and substituted collectors, but the mandatory `expected` values are not defined in a way that the public analyzer can populate for execution-only facts. `trail impact --from A --to B --json --schema-version 2` receives no profile, discovered runner inventory, receipt ID, or actual execution environment from G2. Nevertheless `runner`, `inventory`, and `baseline` are mandatory requirements with an expected value, with baseline described as a compatible receipt identity and coverage. A G1 analyzer using only those CLI arguments cannot determine which profile or receipt G2 will use. If it guesses, G2 will reject legitimate reports or compare a value not bound to the actual execution; if it fabricates a self-asserted value, the trust guarantee is weakened.

Specify how each required expectation can be generated from the supported analyzer inputs. For execution-only facts, use registry-defined predicates or requirement descriptors that G2 evaluates from its independent collectors and separately binds to its receipt and execution report, or define an explicitly supported context input and strict validation. Explain which values are known to G1 versus supplied and verified by G2. Test `trail impact` invoked directly with only the documented arguments followed by G2 using a valid compatible baseline, profile and actual inventory; confirm sparse execution can succeed while forged values and mismatches fall back.
