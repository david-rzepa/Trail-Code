# Conditional schema test review

Changes requested. The new subprocess fixtures exercise the practical two-chain Node/TypeScript case, require a conditional report and a narrow first-target closure, retain v1 fallback and reject unsupported schema versions, and cover dynamic imports, unresolved imports and side-effect imports. The targeted run measured 3.8 seconds for the new suite and is red because schema selection is not yet implemented; the three existing suites passed at the test checkpoint. Those observations do not yet prove conditional behavior works.

The v2 success test checks its schema number, commit IDs and requirement descriptors, but does not validate the required v1 report fields retained by v2. In particular, it never checks `analysis_identity` or endpoint tree and fingerprint identities, and does not validate the shape/provenance of affected entries, changes, gaps or fallback entries. A v2 command can pass these tests while omitting analyzer/policy identity or tree identity that G2 must use to validate reports, cache and receipt compatibility. Extend the real-CLI v2 checks with a shared version-aware validator (or equivalent explicit assertions) covering every mandatory retained field and type, reason provenance and gap/fallback/status consistency, plus deterministic requirement ordering. Keep the two-target sparse assertions and v1 compatibility checks.
