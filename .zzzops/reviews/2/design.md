# Deterministic committed-snapshot planning, execution and evidence

## Outcome and scope

Build a shared deterministic helper and real adapter directly in the Trail-code fork. The initial release accepts exact committed Git endpoints only, works on ordinary Git repositories across supported platforms and filesystems, and never depends on special mounts, Btrfs or privileges. Reject `worktree` explicitly; no implicit HEAD, merge base, or substituted target. Worktree capture and its former acceptance cases are deferred. `docs/test-impact/design.md` remains the contract as amended by the owner's committed-endpoints-only clarification. Consume G1's conservative `trail impact` v1 report, never navigation-oriented `testModules`. Do not invoke a model during runs. Preserve separately runnable original full workflows and prerequisites.

## Planning and analyzer boundary

Validate command options and configuration before work. Require both `--from` and `--to` on all plan/run modes, resolve symbolic inputs exactly once to immutable full commit and tree IDs, and preserve the caller's literal inputs independently for reports. `--profile`, `--all`, `--plan`, `--json` and exit statuses follow the design spec, except that both endpoints are commits. Reject literal `worktree` with a clear error and no receipt. Do not reread moving refs after resolution. Invoke `trail impact --from <resolved-A> --to <resolved-B> --json` via an argv array, never shell text, and validate its v1 fields and types, conservative mode, analyzer/grammar/extractor/resolver/policy identities, both commits, trees, fingerprints, revisions, gaps, fallbacks and status. `comparison.requested` must match the analyzer's literal pinned argv, not the user's original symbolic refs. Reject malformed or contradictory reports and unknown versions/statuses; incomplete/unbounded gaps select the full profile. Bounded gaps map to all dependent scopes or widen to the full profile. Zero analyzer exit means report produced, never tests passed. Capture analyzer logs separately and never execute report text.

Discover actual runnable tests and map affected old/new entities or scopes to target B's surviving runner units; include new and modified tests independently and never schedule deleted units. Apply fixture, resource, generated input, build/configuration and global-hook invalidations; unsupported selectors, dynamic discovery or unknown scope broaden to supported whole targets or the full profile. Preserve original preparation, gate semantics, prerequisites, resource ordering and test-to-test dependencies; a global coverage gate cannot silently become a subset gate. Record calculated impact independently of final execution set, deduplicate only compatible units and deterministically sort with stable reasons while preserving required runner order. A valid empty selection requires complete discovery, reliable impact and compatible passing baseline; failed discovery is not an empty selection. A plan cannot create passing evidence and must be recalculated when snapshot, inventory, context, runner configuration, policy or analyzer identity changes.

Use this fork as the first real integration: its established `npm test` invokes `scripts/run-tests.mjs` to enumerate `test/*.test.ts`, set Git configuration and `GRAFT_NO_TRAIL_SWITCH`, create and clean a temporary directory, and run Node/tsx. Preserve `npm test` as the independently callable full fallback. A file selector may be used only if proven to retain those execution semantics, prerequisites and resource constraints across supported systems; otherwise run the full suite. Preserve `npm run build` and all configured independent gates where required. The deterministic helper owns common validation, planning, receipt compatibility and result rules; a small repository adapter supplies runner-specific discovery and configuration for later setup-skill reuse. Commands are fixed argv arrays or intentional existing scripts, never arbitrary graph-derived shell fragments.

## Exact execution and safe materialization

Committed target B does not itself prove the code executed. Materialize B using ordinary Git/object operations in a fresh private isolated execution root or use a current execution tree only after proving all declared relevant inputs match the resolved tree. Never reset or alter the user's checkout silently. Represent declared generated, ignored and external inputs via pinned configuration, generators, environment identity, always-required gates or a configuration failure. Missing submodules or unsupported required input cannot be treated as unchanged. Isolated execution must keep relevant source bytes and metadata immutable throughout analysis-to-execution and tests while directing declared derived outputs to separate writable locations. If an in-place mode is supported, it requires reliable observation/serialization of all relevant inputs throughout that interval and must invalidate on mutation or observation loss, including edit-and-revert. Before/after hashes alone cannot detect temporary edits. Neither full fallback nor a matching commit alone establishes identity or protection. If a platform cannot establish the required protection, stop as incomplete and issue no receipt; do not silently downgrade the guarantee. Implement and validate a portable ordinary-Git path on supported platforms rather than relying on privileged features; document any unsupported platform and do not claim successful verification there without proof.

For materialization and execution, validate every path component, create and access within the selected root using no-follow or equivalent contained operations, and clean up without following links outside it. Treat committed symlinks as link metadata; only preserve or dereference a link where the entire chain and target are demonstrably within the pinned target tree and safe for the execution environment. Absolute or escaping links, loops, missing targets, unsupported platform semantics, link substitution, or inability to ensure containment require explicit unbounded fallback or stop; never execute a fallback through an unsafe link or read external bytes as part of B. Execute only when the actual runtime input closure and platform symlink behavior remain protected and match B. Analysis fallback cannot make unsafe execution safe. Validate safe contained links, escapes and external sentinel preservation on supported platforms.

## Evidence and receipt trust

Receipt reuse is opt-in through verified evidence, not an implicit baseline guess. After resolving A, load only successful local receipts matching A's complete source identity, requested profile and coverage, target inventory, runner/dependency configuration, relevant non-secret environment identity and analyzer/helper policy. Missing, malformed, unsupported, incomplete, cancelled, failed or incompatible evidence causes full-profile execution at B. Successful full verification creates B's receipt; a selective run creates B's receipt only if the A receipt is compatible and every required target and gate completed, recording the prior receipt dependency. Missing or corrupt chained records, arbitrary subsets, unverified mutations and partial success never establish full evidence. Do not store sensitive values; fingerprint declared values using a policy appropriate for secrets, or use stable non-secret descriptors. Use versioned JSON files in a local repository-scoped store outside the checkout and its Git-controlled or potentially untrusted paths, under a user-owned private state root. Namespace it by stable repository identity; never read, import or migrate receipts from the checkout, Git contents, environment-specified arbitrary paths, or an untrusted shared cache. Before each read or write, verify the state root, namespace, path components, receipt file ownership and private permissions; reject symlinks, non-regular files and unsafe parents, and use directory-relative no-follow operations or a platform equivalent that prevents replacement between validation and use. Do not create a trusted store through a preexisting untrusted path. Fail closed to a full profile if receipt provenance cannot be established; fail verification entirely if even a safe full run or safe receipt publication cannot be established. Publish only after successful completion using exclusive creation and an atomic rename or equivalent, with collision/race handling and no partial or overwritten evidence. Bind each receipt and its entire predecessor chain to the trusted store and validate every link; content hashes alone do not authenticate untrusted receipts. A schema-valid tracked or copied-in JSON file is not evidence. The trust boundary protects against untrusted checkout content and other local users under filesystem access controls; it does not protect against a malicious process running as the same local user or against executing malicious tests with that user's privileges. Where that trust assumption does not hold, do not reuse local evidence. Treat no trustworthy record as missing. Receipt retention/garbage collection and importing CI receipts are future work. The exact on-disk schema and executable/config field spellings remain proposed interface details to be validated in implementation and review rather than silent assumptions.


## Analyzer integration and report

The helper validates G1's owner-approved `trail impact --from <commit> --to <commit> --json` contract and version 1 schema. Require both `comparison` endpoints to be commit kind with full IDs and exact trees; fingerprints and policy identities are evidence inputs, not proof of actual execution. Check analyzer `comparison.requested` against its literal resolved SHA argv, preserve the user's original ref separately and validate resolved tree identities. Enforce complete/bounded/incomplete status and fallback consistency, rejecting unknown versions or contradictory reports. Report versions, original/resolved endpoints and execution identity, actual inventory and affected units, final units and reasons, fallback and baseline evidence status, process results, identity and verification status, and successful receipt ID only when supported. `--json` writes one object to stdout and logs to stderr; plan mode says not run and not verified. A valid full run can establish evidence after incomplete impact only when exact execution identity and all gates independently hold.

G1's injected Git-object, materialization and cache seams are internal test-only boundaries, never public APIs or environment flags. G2 production code uses the supported analyzer contract; test its own validation and fault handling using controlled doubles as well as real production Git/subprocess wiring. Do not treat injection tests as proof of real filesystem containment or mutation observation.

Verify real production wiring on ordinary supported platforms without relying exclusively on fakes, mounts, elevated privileges or special filesystems.

## Alternatives and risks

Historical isolated checkout execution is optional; failure to prove B is a mismatch or incomplete result, not validation. Per-case selection, runtime coverage as sole evidence, implicit baseline trust, and CI receipt import are deferred. The major risk is proving mutation protection portably: do not claim protection based only on read-only permissions, a temporary directory or final hashes. If the supported platform cannot establish it, refuse verification and surface that limitation; broadening selection cannot fix unsafe identity. Sensitive environment values must not appear in reports. Analyzer support remains conservative and may require a full suite frequently.
