# Re-review: multilingual impact and owner-directed execution

Resolved `review_design:10:1`: the design now describes practical target preflight and reports the stable-input assumption without demanding continuous mutation monitoring, while preserving analysis from pinned Git trees independently of the checkout.

The multilingual coverage requirement still admits a vacuous implementation: acceptance requires two-target sparse plans only "in each demonstrably supported slice," without requiring any non-Node slice to be demonstrably supported. Python and Go fixture projects could be analyzed only with full-profile fallback, while Node alone supplies the two-target case. That passes the stated acceptance without delivering a practical multilingual graph-based selection. Name the intended minimum supported language/build slices and require at least one real sparse two-target case for more than one ecosystem (including a non-Node ecosystem), with scoped and unbounded fallback tests retained for constructs outside those slices. This makes the owner's multilingual direction observable while avoiding claims of complete coverage for every upstream parser.
