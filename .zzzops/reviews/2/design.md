# Deterministic planning, execution and verification evidence

## Outcome

Provide a deterministic shared planning/execution helper and a concrete adapter for this Trail-code repository. The adapter supports the explicit endpoint and reporting contract in `docs/test-impact/design.md`, and is an integration example for the later setup skill. It consumes G1's separately identified conservative impact report, never the navigation `testModules` grouping, and executes the existing test workflow without model involvement. The original full commands remain independently callable.

## Approach

Use Trail-code itself as the initial representative project: it is a real Node/TypeScript project, its established full test entry point is `npm test`, and `scripts/run-tests.mjs` deterministically discovers `test/*.test.ts`, applies required Git environment overrides, creates and cleans a run-specific temporary directory, sets `GRAFT_NO_TRAIL_SWITCH`, and invokes Node with tsx. This makes the example independently repeatable without assuming access to another repository. Preserve `npm test` unchanged as the full-suite fallback and preserve any separately declared build and verification gates (including `npm run build` where the profile requires it). A selective runner adapter must use the same discovery and environment/cleanup semantics and pass validated discovered file paths as argv to the runner, without shell interpolation; first prove file-level execution and prerequisites preserve the full workflow on supported platforms. If that equivalence cannot be established, select the whole suite. Never silently reduce a global build, setup, coverage threshold or other gate. Treat cross-test ordering, shared fixtures, resource use, generated inputs, external dependencies and uncertain subprocess or dynamic registration boundaries as explicit invalidations or full-profile fallback; an ordinary graph edge is not enough to exclude a dependent test.

Factor shared code into an analyzer-independent helper that accepts a validated repository configuration and runner-specific adapters. It validates all identities, versioned contracts, inventory, requested endpoints, evidence and policy, computes a normalized ordered plan with reasons, executes argv arrays and reports results. Configuration describes canonical profile, runner units and directories, full commands, discovery/selection, preparation, invalidation rules, environment identity and always-required gates. The concrete integration supplies repository-specific knowledge; unknown mappings, unsupported selectors, discovery errors or unbounded analyzer gaps select a defensible broader target or the independently callable full profile. Configuration gaps that make even full verification unreliable fail as incomplete. Preserve the analyzer's calculated affected set separately from the final execution set and deduplicate only compatible units; preserve ordering, prerequisite groups and resource constraints.

Resolve `--from` and `--to` once; require both for run, plan and `--all`, allowing `--to worktree` explicitly. `--profile`, `--plan`, `--all`, and `--json` follow the supplied specification. A plan never executes or creates a passing receipt. For committed targets, verify the execution tree matches the exact requested commit and all declared relevant execution inputs; otherwise stop with target mismatch unless a separately supported isolated execution environment is selected. For worktrees, use G1's coherent captured snapshot and matching identity. Protect relevant inputs throughout execution using a genuinely immutable source materialization with separately writable declared outputs, or reliable observation/serialization covering all relevant roots, with invalidation on any event or loss of coverage, including edit-and-revert. Hashes before and after alone are insufficient. If no supported mechanism can prove identity and protection, fail rather than claim a full fallback validates the target. Existing user checkouts are never reset. The adapter must cover pinned subprojects and declared ignored/generated inputs; anything whose effects cannot be pinned or observed must be represented in the environment fingerprint, an always-run target, a broader fallback or a configuration failure as appropriate.

Discover runnable inventory at the target, validate analyzer report schema, identity and analysis status against that same snapshot, map old/new impacts to surviving live units and independently add new and modified tests; deleted tests are never executed. Apply declared fixture, hook, setup, configuration and resource invalidations and preserve all gates. A valid empty selection requires complete discovery, sound impact and compatible baseline evidence. Failed discovery or mapping is not empty selection. Deterministically sort normalized units and explanation reasons, respecting runner-specific ordering requirements. Reject stale or incompatible reusable plans if snapshot, inventory, environment, configuration, helper policy or analyzer identity changed.

Receipt reuse is opt-in through verified evidence, not an implicit baseline guess. After resolving A, load only successful local receipts matching A's complete source identity, requested profile and coverage, target inventory, runner/dependency configuration, relevant non-secret environment identity and analyzer/helper policy. Missing, malformed, unsupported, incomplete, cancelled, failed or incompatible evidence causes full-profile execution at B. Successful full verification creates B's receipt; a selective run creates B's receipt only if the A receipt is compatible and every required target and gate completed, recording the prior receipt dependency. Missing or corrupt chained records, arbitrary subsets, unverified mutations and partial success never establish full evidence. Do not store sensitive values; fingerprint declared values using a policy appropriate for secrets, or use stable non-secret descriptors. Use versioned JSON files in a local repository-scoped store outside the checkout and its Git-controlled or potentially untrusted paths, under a user-owned private state root. Namespace it by stable repository identity; never read, import or migrate receipts from the checkout, Git contents, environment-specified arbitrary paths, or an untrusted shared cache. Before each read or write, verify the state root, namespace, path components, receipt file ownership and private permissions; reject symlinks, non-regular files and unsafe parents, and use directory-relative no-follow operations or a platform equivalent that prevents replacement between validation and use. Do not create a trusted store through a preexisting untrusted path. Fail closed to a full profile if receipt provenance cannot be established; fail verification entirely if even a safe full run or safe receipt publication cannot be established. Publish only after successful completion using exclusive creation and an atomic rename or equivalent, with collision/race handling and no partial or overwritten evidence. Bind each receipt and its entire predecessor chain to the trusted store and validate every link; content hashes alone do not authenticate untrusted receipts. A schema-valid tracked or copied-in JSON file is not evidence. The trust boundary protects against untrusted checkout content and other local users under filesystem access controls; it does not protect against a malicious process running as the same local user or against executing malicious tests with that user's privileges. Where that trust assumption does not hold, do not reuse local evidence. Treat no trustworthy record as missing. Receipt retention/garbage collection and importing CI receipts are future work. The exact on-disk schema and executable/config field spellings remain proposed interface details to be validated in implementation and review rather than silent assumptions.

Produce a versioned machine-readable result separate from the impact report, with requested/resolved identities and actual execution identity, profile, inventory and evidence status, calculated impacts, execution units and argv/preparation references, reasons and fallbacks, execution status, verification status, input identity status, and receipt ID only when established. `--json` reserves stdout for one object and routes child diagnostics separately. Exit 0 for successful verification (or plan generation with explicit not-performed status), 1 for completed tests with failure, 2 for invalid input/incomplete verification, and 130 for interruption; preserve individual process statuses and logs. Reject unsupported schema versions rather than interpreting them loosely.

## Analyzer integration (G1 dependency)

Invoke the owner-approved `trail impact --from <commit> --to <commit|worktree> --json` through an argument array using the resolved immutable commit IDs (or literal `worktree` only for the explicit target). A zero exit means only that an impact report was produced, never that verification passed. A failed invocation, malformed JSON, unsupported schema or unavailable coherent target cannot justify exclusion. Validate the G1 v1 contract field-by-field: `analysis_identity` must specify conservative mode and all analyzer/grammar/extractor/resolver/policy identities; `comparison.requested` must match the literal arguments actually passed to the analyzer (the once-resolved commit IDs, or literal `worktree`), and the analyzer commit/tree and worktree fingerprint must match the helper’s separately resolved immutable identities and protected target. Preserve the user’s original symbolic arguments independently in the execution report alongside the resolved IDs and analyzer arguments; do not compare those user literals to analyzer literals or re-resolve symbolic refs after invocation; `changes`, `affected`, `analysis_gaps`, and `required_fallback_scopes` must be present with the required types and path/revision provenance; and `analysis_status` must be consistent with gaps and fallbacks. `incomplete` requires full-profile fallback, and every unbounded gap must carry a full-profile fallback. Bounded fallbacks must map to dependent runner targets or widen to full profile. Unknown status, contradictions or unsupported details are unusable for sparse selection. Never assume a valid empty `affected` list if gaps or failed capture are present. A valid full run may still verify B when analysis is incomplete only if execution snapshot protection and all full-profile requirements independently hold.

The public analyzer CLI captures `worktree` itself; the helper must not infer that a separate capture and analyzer report are the same snapshot merely because they are both called worktree. Bind the validated report's fingerprint and exact captured content to the protected execution identity. Keep a single reliable observation/serialization interval covering analyzer capture and execution where using an in-place tree, or analyze and execute the same immutable materialization through an explicitly supported G1 interface. If neither can establish that identity continuously, refuse verification and receipt creation, even if the full suite passes. A CLI error that provides no coherent report is not a valid impact result. G1’s internal injected capture/cache boundary is a non-public test seam only, not a package export, environment flag or supported caller API. G2 production code must not depend on its test fakes; test the actual supported analyzer interface and production wiring, using deterministic observation and receipt-store fault injection in helper tests only as a supplement. A genuine immutable point-in-time snapshot remains coherent when the live tree changes after acquisition; live-observation mode instead invalidates on relevant mutation or lost coverage. Neither mode proves execution identity without the independent binding and protection above. Verify these bindings with subprocess tests for differing captures, edit-and-revert, observer loss, invalid status/fallback combinations and analyzer nonzero exit. Test symbolic refs and a branch moving after initial resolution: the analyzer receives and reports the pinned commit ID, the execution report preserves the original ref, and moving the branch never changes the selected identity or rejects the otherwise valid report.

## Verification

Use controlled temporary Git histories, real runner invocations and simulated analyzer reports to prove missing arguments fail, diverged endpoints are exact, new/modified tests run, deletions are unscheduled, changed fixture/config invalidation reaches dependent targets, unknown mappings and analysis gaps broaden or block, empty discovery differs from valid empty selection, and plan mode never writes evidence. Exercise same-commit full baseline, missing/incompatible environment/profile/inventory receipts, selective receipt chains and corrupt/partial records; a failed, interrupted or mutated run must not create successful evidence. Test committed-target mismatch, coherent staged/unstaged/untracked capture, mutation including edit-and-revert during capture/execution and observer overflow/failure. Verify selection equivalence with the real `npm test` adapter on meaningful fixtures, preserve the runner's temporary directory and Git overrides, and explicitly exercise full fallback without wrapper recursion. Validate deterministic ordering, JSON stdout isolation, original child failures, signals, and global build/gate behavior. Test serialized and concurrent publication of receipts and incomplete writes; forge a valid-looking tracked receipt in a checkout and ensure it cannot skip the full profile, reject receipt files or state roots with unsafe ownership or permissions, symlinked or replaced path components, non-regular files, and copied/imported records, and reject an unsafe or missing predecessor in a receipt chain. Verify that no untrusted location becomes a trusted store via creation or path substitution. Cover relevant target paths and files with adversarial names through argv execution and submodule/input gaps. CI import and historical isolated checkout are not required for the initial release.

## Alternatives and risks

Per-test-case selectors are deferred until a runner proves stable discovery and selection; file-level or full-suite execution is safer. Runtime coverage as exclusive evidence, implicit HEAD/merge-base selection, trusting absence of graph edges, arbitrary user assertions of passing baseline, and direct interpretation of graph data as shell commands are rejected. Snapshot protection across operating systems is a significant risk: do not advertise support or record passing verification where the underlying mechanism cannot reliably observe or isolate mutations. The analyzer may conservatively return unbounded gaps often, so sparse speedups are not guaranteed; measure them in the end-to-end validation goal. This work does not implement the G1 analyzer, the setup skill, third-party CI evidence, or external service state inference.
